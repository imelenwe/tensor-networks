Layer Gradient Code

A method-by-method guide to hadron-aqc/layer_gradient/simplified/. For each method: what it does, what goes in and what comes out, why it exists, and one real example on 3 qubits. The idea behind the method is in the Circuit Backprop Workbook, section 6; chains, splits and trimming are in the Tensor Chain Workbook. This page starts where workbook 6.8 ("How the real code does it faster") ends. The code: layer_gradient/simplified/ (its own map: CODE_MAP.md).

0. Before you start

Which version runs? Training uses source/ by default: the collaborator's original files, unchanged. simplified/ is our shorter rewrite of the same method. Both pass the same 8 tests, and their slopes agree.

This page reads simplified/, because it is shorter. To run it, set LAYER_GRADIENT_VERSION=simplified.

The example on this page

The example is the workbook's 3-qubit circuit. The physics circuit starts with an X on q1 (start |010⟩). Then come three physics gates: a pair gate on q0, q1, a SWAP on q1, q2, and an electric gate on q0, q1. Each physics gate becomes one block of the trainable circuit.

The trainable circuit comes from IBM's library (qiskit-addon-aqc-tensor, function generate_ansatz_from_circuit). It always starts from |000⟩. The library folds the X on q1 into the one-qubit boxes of the first blocks. It also moves one-qubit rotations between neighbour blocks. So one block on its own is not exactly one physics gate. Only all blocks together equal the physics circuit (checked: the final state equals Qiskit's statevector).

All numbers on this page come from running the code on this example (max_bond 64, stride 6, complex128). The page writes θ names, like the workbook; the code uses the angle numbers.

One difference from the workbook. The loop variables in the code count layers 0, 1, 2. The workbook, and the docstring at the top of forward_backward_pass.py, count them 1, 2, 3. So the docstring's "layer k, S_(k−1), B_k" is this page's "layer n = k − 1, Sn, Bn+1".

Box and block: the two words to know first

This is IBM's trainable copy of the 3-qubit example. Every drawn box with θ's in it is one box.

A box is one instruction of the trainable circuit. The angles live in the boxes. There are two kinds:

boxacts onwhat it doesangles
ZXZone qubitturns the qubit: Rz, then Rx, then Rz3 (2 for the first box on a qubit)
KAKtwo neighbour qubitsmakes the two qubits act on each other: exp(i(a XX + b YY + c ZZ))3 (2 when ZZ is locked at 0: pair and electric)

The picture has 12 boxes: 9 ZXZ boxes and 3 KAK boxes.

A block is a group of boxes that the code multiplies into one 4 × 4 matrix. The grouping rule:

  • Each KAK box starts one block.
  • The ZXZ boxes that come after a KAK box, on its two qubits, join that block.
  • The ZXZ boxes at the very start of a qubit join the first block on that qubit.
blockon qubitsits boxesangles
0 (pair)q0, q1start ZXZ of q0, start ZXZ of q1, KAK, ZXZ on q0, ZXZ on q12 + 2 + 2 + 3 + 3 = 12
1 (SWAP)q1, q2start ZXZ of q2, KAK, ZXZ on q1, ZXZ on q22 + 3 + 3 + 3 = 11
2 (electric)q0, q1KAK, ZXZ on q0, ZXZ on q12 + 3 + 3 = 8

So 12 boxes become 3 blocks, with 12 + 11 + 8 = 31 angles. There is one block for each physics gate (pair, SWAP, electric).

Why two words. The box is what IBM's circuit has: it is where the angles are. The block is what the forward and backward passes use: they only see 4 × 4 matrices on two neighbour qubits. read_boxes finds the boxes, merge_into_blocks groups them, and block_matrices multiplies each group into its 4 × 4 matrix (sections 2 and 3).

The 16 numbers of a block matrix are not angles. The code computes them from all the block's angles.

1. One call, top to bottom

scipy's L-BFGS-B calls the objective at least once per training step. It sends the angles. It gets back L and one slope per angle. This is everything that happens in one call, on the 3-qubit example:

scipy (L-BFGS-B) sends 31 angles
  ▼
LayerGradientObjective(angles)
  [objective.py]

1. block_matrices(blocks, boxes, angles)
   [two_qubit_blocks_to_matrices.py]
   → 3 block matrices (4 × 4)
   → 31 change matrices (4 × 4),
     one per angle: 12 + 11 + 8
   gates = [(block.site, matrix)]

2. forward_and_backward(gates, ...)
   [forward_backward_pass.py]
   split_into_layers → [[0], [1], [2]]
   forward: S0 → S1 → S2 → S3
     (apply_layer → apply_block)
   o = overlap(T, S3)
     = 0.906316 − 0.136132i
   backward, layer 2, then 1, then 0:
     layer_tables(B, S before)
       → 1 table per block
     apply_layer(..., undo=True) on B
   → o, 3 tables (4 × 4),
     3 layer overlaps

3. loss_and_slopes(o, tables, changes, 31)
   [objective.py]
   → L = 0.160060, 31 slopes
  ▼
scipy gets (L, 31 slopes)

The angles never change inside one call. scipy changes them between calls.

LayerGradientObjective(ansatz, target_mps, settings)

objective.py

__init__Runs once per training. ansatz = the trainable circuit, target_mps = T from quimb, settings = max_bond, stride, use_gpu, single_precision. It calls read_boxes (12 boxes), merge_into_blocks (3 blocks) and target_as_chain (T as a chain). It picks numpy or cupy as xp, and complex128 or complex64 as the number type.
__call__objective(angles) → (L, slopes). scipy calls this.
_passesSections 3 to 5: block matrices, then forward_and_backward. It converts each block matrix to an xp array of the chosen number type, as a gate (site, matrix). Then __call__ runs loss_and_slopes (section 6). On a GPU it first copies the tables back to normal memory.
layer_overlapsReturns the layer overlaps (section 5), for the test.

Errors: it stops if T has a different number of sites than the circuit has qubits.

2. Setup, once per training

LayerGradientObjective.__init__ (section 1) runs these three methods once.

read_boxes(ansatz)

two_qubit_blocks_to_matrices.py

doesMakes one Box per instruction of the trainable circuit. A Box keeps its qubits, the numbers of its angles, and a function that gives its matrix for any angles.
inthe trainable circuit (Qiskit)
outa list of Box
whyThe angles change every call, but the circuit's shape never changes. The Box keeps the shape and computes only the matrix again.

Example. The 3-qubit circuit gives 12 boxes:

boxtypequbitsθ names
0, 1, 2ZXZ (start)0; 1; 2θ0 θ1; θ2 θ3; θ4 θ5
3KAK (pair)0, 1θ6 θ7 (θ8 locked)
4, 5ZXZ0; 1θ9–θ11; θ12–θ14
6KAK (SWAP)1, 2θ15–θ17
7, 8ZXZ1; 2θ18–θ20; θ21–θ23
9KAK (electric)0, 1θ24 θ25 (θ26 locked)
10, 11ZXZ0; 1θ27–θ29; θ30–θ32

A locked angle is a fixed 0.0 inside its box, so the Box does not list it.

Line by line 
position = {angle: i for i, angle in enumerate(ansatz.parameters)}
for instruction in ansatz.data:
    qubits = tuple(ansatz.find_bit(qubit).index for qubit in instruction.qubits)
    alone = QuantumCircuit(len(qubits))
    alone.append(instruction.operation, list(range(len(qubits))))
    angles = list(alone.parameters)
    indices = tuple(position[angle] for angle in angles)
    if not angles:
        fixed = np.asarray(Operator(alone).data)
        boxes.append(Box(qubits, indices, lambda x, fixed=fixed: fixed))
        continue
    def matrix_at(x, alone=alone, angles=angles, indices=indices):
        values = {angle: float(x[i]) for angle, i in zip(angles, indices)}
        return np.asarray(Operator(alone.assign_parameters(values)).data)
    boxes.append(Box(qubits, indices, matrix_at))

The loop also skips barriers (if instruction.operation.name == "barrier": continue).

linewhat it does
positiongives each angle object its number, 0 … 30
alonea small circuit (1 or 2 qubits) with only this one instruction
indicesthe numbers of the angles that this box uses
if not anglesa box with no trained angle has one fixed matrix; compute it once
matrix_at(x)x is the full list of 31 angles. The function picks this box's angles from it, puts them in, and asks Qiskit's Operator for the matrix
alone=alone, …freezes the current box's values inside the function (a Python detail; without it, every function would see the last box)

Limit: Operator builds the matrix from a circuit, which is slow (section 7). The matrix is in Qiskit's bit order; _on_block converts it to the chain's order.

target_as_chain(target_mps)

objective.py

doesConverts our quimb target to the chain format: a list of arrays with the index order (left link, 0/1, right link).
inthe target from build_target_using_lib (quimb)
outa list of arrays, site q = qubit q
whyquimb gives the two end sites only two indices, and it names indices by text. The passes want three indices on every site, in a fixed order.

Example. T becomes three sites with shapes (1, 2, 2), (2, 2, 2), (2, 2, 1). array[None] and array[..., None] add a link of size 1 at each end.

Note: the backward pass calls move_centre(target_side, 0, n_qubits − 1), so it tells move_centre that the centre is at site 0. For the quimb target this is not true, but it does not matter. The move QR-splits every site from 0 to the second-to-last. Each split leaves a plain rotation behind, whatever the site's form was. After the move, the centre really is at the last site (why T needs a centre: section 5).

3. Angles → block matrices

block_matrices(blocks, boxes, angles)

two_qubit_blocks_to_matrices.py

doesFor every block, computes (1) its 4 × 4 matrix at these angles and (2) for each of its angles, its change matrix.
inblocks, boxes, the 31 angles
outmatrices: 3 matrices (4 × 4). changes: per block, a list of (angle number, 4 × 4)
whyThe passes need the matrices. The chain rule (section 6) needs the change matrices.

Example: the matrix of block 0 (pair). It has 5 parts, P1 … P5 in the order applied. The block matrix is their product, the last part on the left:

block 0 = P5 · P4 · P3 · P2 · P1
        = ZXZ(q1) · ZXZ(q0) · KAK · start ZXZ(q1) · start ZXZ(q0)

Example: the change matrix of block 0 for θ[6]. Only P3 (the KAK) holds θ[6]. So only P3 changes. The other parts stay as they are (the product rule):

Step 1. Change matrix of the box alone (a nudge, NUDGE = 10⁻⁶):
        dP3 = ( KAK(θ6 + 10⁻⁶) − KAK(θ6 − 10⁻⁶) ) / (2 × 10⁻⁶)

Step 2. Put the other parts around it:
        change = (P5 · P4) · dP3 · (P2 · P1)

        P5 · P4: the parts after P3
        P2 · P1: the parts before P3

This change matrix agrees with a nudge of the whole block to 6 × 10⁻¹¹. All three block matrices are unitary to 4 × 10⁻¹⁶.

Line by line

for part in parts:
    before.append(part @ before[-1])
after = [np.eye(4, dtype=complex)]             # after[k] = the last k parts
for part in reversed(parts):
    after.append(after[-1] @ part)
matrices.append(before[-1])
...

linewhat it does
partsevery part's matrix, already as a 4 × 4 in the chain's order
beforerunning products from the start. For block 0: before[2] = P2 · P1
afterrunning products from the end. For block 0: after[2] = P5 · P4
before[-1]all 5 parts: the block matrix
up, downcopies of the angles with one angle moved by +NUDGE and −NUDGE
change +=for θ[6], k = 2 (P3): after[5 − 1 − 2] = after[2] = P5 · P4, before[2] = P2 · P1. The += adds up when two boxes of one block share an angle (none do in our circuits)

Why the running products: they are built once per block. After that, each angle costs only two 4 × 4 products.

Limit: the change matrices come from nudges, not exact derivatives. They agree with exact ones to about 10⁻¹⁰. Each change matrix needs two more Operator calls. At 12 qubits this is 61% of the time; at 20 qubits with max_bond 256 it is 5% (section 7).

_on_block(matrix, qubits, where)

two_qubit_blocks_to_matrices.py

doesPuts one box's matrix into its block's 4 × 4 frame, in the chain's bit order.
ina box matrix (2 × 2 or 4 × 4), its qubits, its place
outa 4 × 4 matrix
whyQiskit and the chain number the two qubits in opposite orders.
placeresult
"first"kron(matrix, I₂): acts on the block's first site
"second"kron(I₂, matrix): acts on the second site

Example: why 1 and 2 change places. Take the state "q0 = 1, q1 = 0". Qiskit puts the first qubit on the last bit: binary 01 = index 1. The chain puts the first site on the first bit: binary 10 = index 2. So Qiskit's row 1 is the chain's row 2, and the reverse. Rows 0 (00) and 3 (11) do not move.

4. Forward pass

forward_and_backward(gates, n_qubits, target, max_bond, cutoff, xp, stride, keep, restore)

forward_backward_pass.py

doesThe forward pass (this section), then the backward layer pass (section 5).
ingates (the blocks as (site, 4 × 4), in circuit order), the number of qubits, T, max_bond, cutoff (10⁻¹²), xp, stride, and keep / restore (how to save a state and get it back)
outvalue = o; tables = one 4 × 4 table per block, in block order (the same order as the change matrices, so loss_and_slopes can pair them with zip); layer_overlaps, last layer first
whyOne function, so the kept forward states never leave it.

The first half applies the layers to |0…0⟩, keeps a copy of the state before every stride-th layer, and computes o.

layers = split_into_layers(gates, n_qubits)
state, centre, kept = all_zeros_chain(n_qubits, xp, target[0].dtype), 0, {}
for number, layer in enumerate(layers):
    if number % stride == 0:
        kept[number] = (keep(state), centre)
    centre = apply_layer(state, centre, gates, layer, max_bond, cutoff, xp)
value = overlap(target, state, xp)

In this file a gate is two values: a block's site and its 4 × 4 matrix. gates lists all blocks in circuit order.

layer (code)blockcentresite shapes after
start0(1,2,1) (1,2,1) (1,2,1)
0pair, site 00 → 1(1,2,2) (2,2,1) (1,2,1)
1SWAP, site 11 → 2(1,2,2) (2,2,2) (2,2,1)
2electric, site 02 → 0(1,2,2) (2,2,2) (2,2,1)

Then o = ⟨T|S3⟩ = 0.906316 − 0.136132i, the same as the exact value.

Kept states. With stride 6, the code keeps only the states before layers 0, 6, 12, …. In the 3-qubit example that is only S0. The backward pass rebuilds S1 and S2 from S0 (section 5). The workbook's table in 6.3 marks S1 and S2 "kept": that is the picture for stride 1.

At 12 qubits (35 layers), stride 6 keeps 6 states: before layers 0, 6, 12, 18, 24, 30. Stride 1 keeps 35.

Memory: the backward pass also holds the rebuilt states of one stretch, up to stride of them. So the states in memory are about (layers ÷ stride) + stride. For 35 layers that is smallest near stride 6 (6 + 6 = 12, against about 36 for stride 1 or for stride 35). The rebuild costs at most one extra forward pass.

Why a copy is cheap: no function changes an array in place. A function always writes a new array into the list. So on the CPU, list(state) (and keep=list) is a full snapshot that costs only a new list. On a GPU, keep copies the chain to normal memory, and restore copies it back.

The centre is kept with each state, because apply_layer needs it when the rebuild starts.

split_into_layers(gates, n_qubits)

forward_backward_pass.py

doesPuts each block into the first layer after the last block on its two qubits.
inthe blocks as (site, matrix), the number of qubits
outa list of layers; each layer is a list of block numbers
whyBlocks in one layer share no qubit. So one sweep from the left and one from the right give the tables of all of them (section 5).

Example. The blocks sit at sites 0, 1, 0. first_free_layer[q] is the first layer where qubit q is free.

start:    first_free_layer = [0, 0, 0]
block 0 (q0, q1): max(0, 0) = 0 → layer 0;  now [1, 1, 0]
block 1 (q1, q2): max(1, 0) = 1 → layer 1;  now [1, 2, 2]
block 2 (q0, q1): max(1, 2) = 2 → layer 2;  now [3, 3, 2]
result: [[0], [1], [2]]

Every block uses q1, so every block waits for the one before it.

At 12 qubits, 153 blocks give 35 layers. The layers repeat in groups of six. The six layers hold: 6 pair blocks; 5 SWAP blocks; 4 pair and 2 electric blocks; 2 SWAP blocks; 4 electric blocks; 3 SWAP blocks. The 3-SWAP layer starts the next Trotter step, and the circuit's first step has no such layer. So 6 steps give 6 × 6 − 1 = 35 layers.

Limit: the layers follow which qubits are free, not the Trotter sub-layers. The two end electric blocks are free early, so they go one layer ahead of the other four. The circuit is the same.

all_zeros_chain(n_qubits, xp, dtype)

tensor_chain.py

apply_layer(chain, centre, gates, layer, max_bond, cutoff, xp, undo=False)

forward_backward_pass.py

doesApplies all blocks of one layer, one after another. It goes left to right or right to left, from the end nearer the centre. With undo=True it applies each block's conjugate transpose.
ina chain, its centre, the layer
outthe new centre. The function writes new arrays into the caller's list chain: the list changes; no array does
whyEach block needs the centre next to it. Each move of the centre by one site costs one QR split. Start at the near end, and the centre moves the least.

Example. Layer 2 (electric, site 0) with the centre at site 2. The middle of the layer is (0 + 1) / 2 = 0.5. The centre 2 is right of 0.5, so the layer goes right to left. weights_go_right=False, and the centre ends at site 0.

Why weights_go_right = rightwards: after each block, the weights go to the side of the next block in the sweep. So the centre is already next to the next block, and no extra move is needed.

apply_block(chain, centre, site, block, max_bond, cutoff, xp, weights_go_right=True)

tensor_chain.py

doesApplies one 4 × 4 block to sites (site, site + 1), splits them again, and trims.
ina chain, its centre, the block
outthe new centre
whyThis is the one place where the state changes. Every other function only reads or moves.

Example: the pair block on S0 = |000⟩.

Step 1. Move the centre to the block:
        centre stays 0
Step 2. Join sites 0 and 1 into one array:
        (1, 2, 2, 1) = (left, in1, in2, right)
Step 3. Apply the block:
        (2, 2, 1, 1) = (out1, out2, left, right)
Step 4. Make a matrix:
        rows (left, out1) = 1 × 2 = 2
        columns (out2, right) = 2 × 1 = 2
Step 5. Split it with an SVD:
        weights 0.935897, 0.352274
Step 6. Trim (max_bond 64): keep 2
Step 7. Weights go into the right site:
        (1,2,2) (2,2,1) (1,2,1), centre 1

The same with max_bond 1: step 6 keeps 1 weight. The shapes become (1,2,1) (1,2,1) (1,2,1). The code does not rescale, so the state's length² drops to 0.935897² = 0.875903.

Line by line 
centre = move_centre(chain, centre, site if centre <= site else site + 1, xp)
left, right = chain[site].shape[0], chain[site + 1].shape[2]
pair = xp.tensordot(chain[site], chain[site + 1], axes=(2, 0))                     # (left, in1, in2, right)
pair = xp.tensordot(block.reshape(2, 2, 2, 2), pair, axes=([2, 3], [1, 2]))        # (out1, out2, left, right)
u, weights, vh = xp.linalg.svd(pair.transpose(2, 0, 1, 3).reshape(left * 2, 2 * right), full_matrices=False)
kept = max(1, min(max_bond, int((weights > cutoff * weights[0]).sum())))           # trimming
u, weights, vh = u[:, :kept], weights[:kept], vh[:kept]
if weights_go_right:
    chain[site], chain[site + 1] = u.reshape(left, 2, kept), (weights[:, None] * vh).reshape(kept, 2, right)
    return site + 1
chain[site], chain[site + 1] = (u * weights).reshape(left, 2, kept), vh.reshape(kept, 2, right)
return site
linewhat it does
move_centre(...)moves the centre to the nearer of the two sites
pair = tensordot(…, axes=(2, 0))joins the two sites over their shared link
block.reshape(2, 2, 2, 2)views the 4 × 4 block as [out1, out2, in1, in2], then sums over in1, in2
transpose, reshapemakes a matrix: rows (left, out1), columns (out2, right)
svdsplits it: u (left site), weights, vh (right site)
kept = …count the weights above 10⁻¹² × the largest; take at most max_bond; take at least 1
weights_go_rightTrue: the weights join vh, and the centre is site + 1. False: they join u, and the centre is site

Why the centre matters: when the centre is at the block, the SVD weights are the weights of the whole state. Then dropping the smallest weights loses the least of the state. Limit: trimming lowers length², and the code does not rescale it. With a small max_bond, L and the slopes are wrong: at max_bond 1, L = 0.486 (exact 0.160), and slopes are off by up to 0.9. At max_bond 2 they are exact.

move_centre(chain, centre, to, xp)

tensor_chain.py

doesMoves the centre one site at a time with a QR split. To move right: the site keeps Q (a plain rotation), and R goes into the next site. To move left: reshape the site as (left, 2 × right), transpose it, then QR. The site keeps Qᵀ, and Rᵀ goes into the site on the left.
ina chain, the centre now, the site to move to
outthe new centre (= to)
whyQR is cheaper than SVD, and it is exact: it trims nothing. The state does not change.

Example. A chain with links larger than needed: (1,2,4) (4,2,4) (4,2,1). Move 0 → 1: the first site has only 1 × 2 = 2 rows, so Q has 2 columns. The link shrinks to 2: (1,2,2) (2,2,4) (4,2,1). After a QR split, the new link size is the smaller of two sizes: the old link size, or 2 × the link size on the site's other side. The split never changes the state. (Only the trim in apply_block drops weights.)

moving right, one step:
q, r = qr( chain[centre].reshape(left * 2, right) )
chain[centre]     = q  → shape (left, 2, new link)
chain[centre + 1] = r · chain[centre + 1]

tensor_chain.py

5. Backward layer pass

The second half of forward_and_backward. It goes from the last layer to the first. At each layer it joins the state before the layer with the target side after it, into one table per block. Then it undoes the layer on the target side.

The backward loop

forward_backward_pass.py, inside forward_and_backward

target_side = list(target)
target_centre = move_centre(target_side, 0, n_qubits - 1, xp)
for number in reversed(range(len(layers))):
    if number not in states_before:        # rebuild this stretch of states, once
        first = number - number % stride
        state, centre = kept.pop(first)
        state = restore(state)
        states_before = {first: state}
        for earlier in range(first, number):
            state = list(state)          # a new list: the stored state stays as it is
            centre = apply_layer(state, centre, gates, layers[earlier], max_bond, cutoff, xp)
            states_before[earlier + 1] = state
    these_tables, layer_overlap = layer_tables(target_side, states_before.pop(number), gates, layers[number], xp)
    ...store the tables
    target_centre = apply_layer(target_side, target_centre, gates, layers[number], max_bond, cutoff, xp, undo=True)

Why target_side = list(target): it makes a new list, so the undo never touches self.target, and T stays as it is for the next call.

Why the target side needs a centre: undo applies blocks and trims, the same as the forward pass. Trimming is best at the centre. So the code first moves T's centre to the last site.

Example. A round is one pass through the loop, for one layer. There are three rounds, last layer first. Layer n (code number) takes Sn to Sn+1. The round computes ⟨bra| layer n |ket⟩ = ⟨Bn+1|Sn+1⟩.

layer nket

In all three rounds, ⟨bra| layer n |ket⟩ = 0.906316 − 0.136132i = o.

Round 1 needs S2, but the forward pass did not keep it. So the code takes the nearest kept state, S0 (first = 2 − 2 % 6 = 0), and applies layers 0 and 1 again. It stores S0, S1, S2 in states_before. Rounds 2 and 3 then find their states ready.

The check: every layer overlap equals o (here to 10⁻¹⁵). Sk is the final state with the later layers taken off. Bk is T with the same layers undone. Taking the same layers off both sides keeps the overlap (workbook 6.5). With trimming, the layer overlaps can drift apart a little. The test test_backward_layer_pass_keeps_the_overlap checks this. A wrong undo or a wrong bit order breaks it at once.

layer_tables(bra, ket, gates, layer, xp)

forward_backward_pass.py

doesGives one table for every block of one layer, from one sweep from the left and one from the right. It also gives ⟨bra| layer |ket⟩.
inbra = the target side after the layer, ket = the state before it, the layer
out{block number: 4 × 4 table}, and the layer overlap
whyWithout the two sweeps, each block's table needs one full sweep along the chain. With them, a layer of 6 blocks needs 2 sweeps, not 6.

Step 1: cut the chain into pieces. A piece is one block (two sites) or one empty site. Layer 2 (electric on sites 0, 1) on 3 qubits gives 2 pieces: (site 0, block 2) and (site 2, empty).

Step 2: two sweeps, every partial result kept. from_left[p] holds pieces 0 … p − 1, joined. from_right[p] holds pieces p, p + 1, …, joined. Each is a small (bra link, ket link) matrix.

from_left:   [ (1,1) nothing,  (2,2) piece 0,  (1,1) pieces 0 and 1 ]
from_right:  [ (1,1) pieces 0 and 1,  (2,2) piece 1,  (1,1) nothing ]

Step 3: one table per block. The table of piece p uses from_left[p] (all left of it) and from_right[p + 1] (all right of it). For the electric block: from_left[0] = (1, 1) and from_right[1] = (2, 2).

Step 4: the layer overlap. from_left[-1] holds all pieces: it is the 1 × 1 number ⟨bra| layer |ket⟩.

Limit: the tables come from trimmed chains. With a small max_bond they are approximate, like everything else.

_table(from_left, from_right, bra, ket, site, xp)

forward_backward_pass.py

doesJoins everything around one block, with the block left out. The result has the block's shape: 4 × 4, [(out1 out2), (in1 in2)].
inthe partial results left and right of the block, bra, ket
outthe 4 × 4 table
whyFor layer n, o = ⟨Bn+1| layer n |Sn⟩. Sn holds only the layers before n. Bn+1 holds only T and the layers after n. So the block appears exactly once, and o is linear in its 16 entries: o = Σ table × block, entry by entry (not a matrix product). Each table entry tells how much o changes per unit change of that block entry. Step by step, with numbers: workbook 6.9.

6. Chain rule → slopes

loss_and_slopes(value, tables, changes, n_angles)

objective.py

doesJoins the tables (section 5) with the change matrices (section 3). Returns L and all slopes.
ino, one table per block, the change matrices, the number of angles
outL, and a list of 31 slopes
whyThe table says how o reacts to each block entry. The change matrix says how each block entry reacts to the angle. The chain rule multiplies the two.

The derivation (symbols).

Step 1. The overlap slope. o depends on block b
        only through its 16 entries:
        do/dθ = Σ over the 16 entries of
                table_b × change matrix_b(θ)

Step 2. L = 1 − |o|² = 1 − o · conj(o)

Step 3. dL/dθ = −( do/dθ · conj(o) + o · conj(do/dθ) )
              = −2 Re( conj(o) · do/dθ )

The example (numbers). o = 0.906316 − 0.136132i, so L = 1 − (0.821409 + 0.018532) = 1 − 0.839941 = 0.16006. With all digits, L = 0.1600598702, the exact value. The slopes:

All 31 slopes agree with a nudge of the exact loss to 1.1 × 10⁻¹⁰. One step, new θ = θ − 0.5 × slope, gives L = 0.1286, as in the workbook (6.7).

overlap_slopes = np.zeros(n_angles, dtype=complex)
for table, block_changes in zip(tables, changes):
    for angle, change in block_changes:
        overlap_slopes[angle] += np.sum(change * table)
return 1.0 - abs(value) ** 2, -2.0 * np.real(np.conj(value) * overlap_slopes)

change * table multiplies entry by entry (16 products), and np.sum adds them. That is step 1. The return line is steps 2 and 3. value is o.

  • The block matrices cost about 1.3 ms per box, for any max_bond. At 12 qubits one call builds 3,081 small circuits for Qiskit's Operator: one per box (471) for the matrices, and two per angle (2,610) for the change matrices.
  • The passes grow with qubits × link size³, once the links reach max_bond in the middle of the chain (before that, more slowly). At max_bond 64: 0.18, 0.86, 1.75, 2.28 s at 12, 16, 20, 24 qubits. At max_bond 256: 3.0, 16.0, 26.6 s at 16, 20, 24 qubits.
  • The most expensive pass is the undo on the target side, because the target starts at its full link size.
  • At 120 qubits the SVDs are everything: one SVD at link size 1024 takes 2.8 s on this CPU. This is why max_bond 1024 needs a GPU.

  • Single precision (complex64) with scipy's SVD: the passes are ×1.3 faster, but the slopes are off by about 3 × 10⁻⁶. numpy's SVD is not faster in single precision on this Mac. So --single-precision today halves the memory but saves no time.
  • Not worth it: other SVD drivers (same or 5–30× slower), BLAS thread settings (the splits use one core), the tables (4–7% of the time), the centre moves (1.2 QR splits per SVD).
  • Not tried yet: the GPU path. It is in the code, but no one has tested it.
  • Not tried yet: a chain form that keeps the weights on every link. It needs no QR splits, which are 25% of the passes at max_bond 256. It also lets one layer's SVDs run at the same time.

The takeaway: at 12–16 qubits with max_bond 64, Qiskit's Operator is the slow part, and formulas fix it (×2–4). At max_bond 256, and from 20 qubits, the SVDs are the slow part. A GPU or fewer SVDs are the likely fixes; neither is measured yet.

For reference, at 12 qubits: jax takes 0.029 s per call after a 17.6 s compile; IBM's explicit gradient takes 1.9 s. jax is the fastest at small sizes, but at 120 qubits it asked for 1.5 TB of memory.

8. For the meeting

The method in three lines

  1. Forward: apply the layers to |0…0⟩ on a trimmed chain, keep every 6th state, compute o = ⟨T|Sfinal⟩.
  2. Backward: from the last layer, join the state before each layer with the target side after it into one 16-number table per block; then undo the layer on the target side.
  3. Chain rule: overlap slope = Σ table × change matrix; slope = −2 Re(conj(o) × overlap slope).

The limits, in one list

  • Trimming is not rescaled (apply_block): with a max_bond that is too small, L and the slopes are wrong. At max_bond 1 on 3 qubits, L = 0.486 against 0.160 exact.
  • The change matrices come from nudges (block_matrices): accurate to about 10⁻¹⁰, not exact.
  • Qiskit's Operator is slow (section 7): 61% of a call at 12 qubits.
  • Only neighbour qubits (merge_into_blocks): fine for our circuits.
  • The GPU path is untested, and max_bond 1024 at 120 qubits needs it.

Open questions

  • Rescale the chain after each trim, or not?
  • Formulas instead of Operator (×2–4 at 12–16 qubits, slopes unchanged): move them into the code?
  • Stride 6 or stride 1: about 15–30% faster for 2× the memory.
  • Who tests the GPU path, and on which machine?
